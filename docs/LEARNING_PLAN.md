# 🗺️ Дорожная карта обучения: Go с нуля до Junior Developer

Подробная программа последовательного освоения языка программирования Go и backend-разработки.

---

## 🎯 Принципы и методология обучения

1. **Обучение с абсолютного нуля**: никакой материал не считается «само собой разумеющимся».
2. **Шаг за шагом**: одна тема за занятие, дробление сложных концепций на небольшие понятные блоки.
3. **Объяснение «почему»**: фокус на внутренних механизмах (память, компиляция, рантайм, планировщик).
4. **Осознанная практика**: отсутствие готовых подсказок до первой самостоятельной попытки решения.
5. **Культура ошибок**: разбор типовых антипаттернов, скрытых ловушек языка и ошибок новичков.
6. **Критерий перехода**: переход к следующей теме возможен только после сдачи практики и ответов на контрольные вопросы (оценка не ниже 7/10 в [docs/GRADES.md](GRADES.md)).

---

## 📅 График и организация

- **Формат:** График 2/2.
- **Длительность:** 2–3 часа (10:00–13:00) в каждый из двух выходных дней.
- **День 1 (выходной):** Теория, анатомия синтаксиса, демонстрационные примеры, разбор «подводных камней».
- **День 2 (выходной):** Самостоятельная практика (3 уровня сложности), детальный Code Review, вопросы на понимание.
- **Рабочие дни:** Отдых либо пассивное повторение конспектов в [docs/NOTES.md](NOTES.md).

## 📚 15 этапов обучения

### Этап 1. Подготовка и первые программы
- **Темы:** Устройство Go, компиляция vs интерпретация, статическая vs динамическая типизация, структура программы, `package main`, функция `main()`, пакет `fmt` (`Println`, `Printf`, `Print`), инструменты `go run` и `go build`.
- **Что должен уметь:** Понимать жизненный цикл Go-программы, компилировать автономные бинарники, использовать форматированный вывод.
- **Практические задания:** Написание первой консольной визитки, эксперименты с флагами компилятора и выявление синтаксических ошибок (скобки `{`, неиспользуемые импорты).
- **Критерий усвоения:** Способность с нуля без подсказок написать и скомпилировать исполняемую программу, объяснить назначение каждой строчки.

### Этап 2. Основы Go: переменные, типы, операторы, условия, циклы
- **Темы:** Явное (`var`) и краткое (`:=`) объявление, нулевые значения (*zero values*), базовые типы (`int`, `float64`, `bool`, `string`), строгая типизация и явное приведение типов, константы и генератор `iota`, арифметические и логические операторы, условия `if / else if / else` (с блоком инициализации), оператор `switch` (включая множественные кейсы и отсутствие `break`), единственный цикл `for` (классический, while-подобный, бесконечный, `break`, `continue`).
- **Что должен уметь:** Свободно оперировать типами, правильно выбирать способ объявления переменных, организовывать ветвление логики и циклические алгоритмы.
- **Практические задания:** Консольный калькулятор с валидацией ввода, мини-игра «Угадай число», конвертер валют и температур.
- **Критерий усвоения:** Отсутствие неявных предположений о типах, корректное использование zero values и написание циклов без утечек ресурсов.

### Этап 3. Функции и область видимости
- **Темы:** Объявление функций, параметры и возвращаемые значения, множественный возврат значений, именованные возвращаемые значения, вариативные функции (*variadic* `...T`), анонимные функции и замыкания (*closures*), оператор `defer` (стек вызовов LIFO, момент вычисления аргументов), области видимости (блок, пакет, экспорт через регистр символов).
- **Что должен уметь:** Декомпозировать код на чистые функции, использовать `defer` для гарантированного освобождения ресурсов, применять замыкания для инкапсуляции состояния.
- **Практические задания:** Модульный калькулятор скидок и налогов, генератор ID на замыканиях, трекер времени выполнения функций.
- **Критерий усвоения:** Понимание порядка выполнения `defer`, области видимости переменных и умение возвращать пару `(результат, ошибка)`.

### Этап 4. Массивы, срезы, map и строки
- **Темы:** Фиксированные массивы и почему они редко используются напрямую; срезы (*slices*): структура (`pointer`, `len`, `cap`), создание через литерал и `make()`, функция `append()` и механика реаллокации базового массива; подслайсинг `[low:high]`; хэш-таблицы (*maps*): создание, чтение, запись, проверка наличия ключа (*comma-ok*), удаление `delete()`, почему порядок ключей рандомизирован; строки: UTF-8, байты vs руны (`rune`), перебор через `for range`.
- **Что должен уметь:** Грамотно управлять емкостью срезов во избежание лишних аллокаций памяти, безопасно работать с maps, корректно обрабатывать Unicode-символы.
- **Практические задания:** Система фильтрации и сортировки списка заказов, подсчет частоты слов в тексте, реверс UTF-8 строки.
- **Критерий усвоения:** Четкое понимание различия между длиной (`len`) и емкостью (`cap`), поведение срезов при передаче в функцию, понимание не-потокобезопасности `map`.

### Этап 5. Структуры, методы и указатели
- **Темы:** Указатели: оператор взятия адреса `&`, разыменование `*`, передача по значению vs по указателю, стек vs куча (*escape analysis* в общих чертах); структуры (`struct`): объявление, инициализация, анонимные структуры; методы структуры: получатель по значению (*value receiver*) vs получатель по указателю (*pointer receiver*); композиция и встраивание структур вместо наследования (*embedding*).
- **Что должен уметь:** Моделировать доменные сущности с помощью структур, правильно выбирать тип получателя метода, избегать лишнего копирования больших структур.
- **Практические задания:** Разработка модели пользователя с кошельком и транзакциями, система управления банковскими счетами с методами депозита и списания.
- **Критерий усвоения:** Точное понимание, когда передавать структуру по указателю, а когда по значению; умение проектировать составные структуры.

### Этап 6. Интерфейсы и композиция
- **Темы:** Философия интерфейсов в Go: неявная реализация (*implicit implementation*, утиная типизация); маленькие интерфейсы (1–2 метода: `io.Reader`, `io.Writer`, `fmt.Stringer`); композиция интерфейсов; пустой интерфейс `any` (`interface{}`); приведение типов (*type assertion* `v, ok := i.(T)`) и проверка типов (*type switch*).
- **Что должен уметь:** Проектировать гибкие слабосвязанные архитектуры, изолировать логику через интерфейсы для последующего тестирования (мокирования).
- **Практические задания:** Система уведомлений (Email, SMS, Push-сервисы, реализующие единый интерфейс), универсальный логгер с выводом в разные источники.
- **Критерий усвоения:** Понимание правила «принимай интерфейсы, возвращай структуры» (*accept interfaces, return structs*).

### Этап 7. Обработка ошибок
- **Темы:** Философия ошибок в Go: «ошибки — это обычные значения» (*values*); интерфейс `error`; функции `errors.New()`, `fmt.Errorf()`; оборачивание ошибок (*wrapping* с флагом `%w`); функции `errors.Is()` и `errors.As()`; создание собственных типов ошибок; паника и восстановление: когда уместен `panic()`, а когда `recover()`.
- **Что должен уметь:** Корректно проверять ошибки без пропуска `if err != nil`, прокидывать контекст через wrapping, безопасно перехватывать критические сбои.
- **Практические задания:** Валидатор конфигурационных файлов с детализированным деревом ошибок, безопасный парсер данных с защитой от паники.
- **Критерий усвоения:** Отсутствие игнорирования возвращаемых ошибок (`_`), умение извлекать корневую ошибку через `errors.Is` и кастомный контекст через `errors.As`.

### Этап 8. Пакеты, модули, generics и работа с памятью
- **Темы:** Организация кода: `go.mod`, `go.sum`, импорты, циклические зависимости (*cycle imports*) и способы их устранения; internal-пакеты; видимость (public/private); основы Generics (Go 1.18+): type parameters, constraints (`comparable`, `any`, пользовательские интерфейсы-ограничители); работа со сборщиком мусора (*Garbage Collector*) и основы оптимизации памяти.
- **Что должен уметь:** Структурировать проект на логические пакеты, писать обобщенные типобезопасные структуры данных и функции.
- **Практические задания:** Разработка собственного generic-стека и generic-очереди, реализация универсальной функции поиска элемента в срезе.
- **Критерий усвоения:** Чистая архитектура без циклических зависимостей, уместное применение generics без оверинжиниринга.

### Этап 9. Конкурентность: goroutines, channels, mutex, context
- **Темы:** Модель многозадачности Go (CSP — Communicating Sequential Processes); запуск горутин `go func()`; каналы: небуферизованные vs буферизованные; чтение, запись, закрытие канала `close()`, чтение через `for range`; конструкция `select` (с `default`, таймаутами); примитивы синхронизации: `sync.WaitGroup`, `sync.Mutex`, `sync.RWMutex`, `sync.Once`; гонки данных (*data races*) и утилита `go run -race`; пакет `context`: отмена операций, дедлайны, передача метаданных.
- **Что должен уметь:** Писать безопасные параллельные программы, предотвращать дедлоки и утечки горутин (*goroutine leaks*), безопасно управлять разделяемым состоянием.
- **Практические задания:** Пул воркеров (*Worker Pool*) для асинхронной обработки задач, конкурентный сканер сетевых портов или ссылок с ограничением concurrency и таймаутом через `context`.
- **Критерий усвоения:** Программа проходит проверку с флагом `-race` без предупреждений, горутины гарантированно завершаются при отмене контекста.

### Этап 10. Работа с HTTP, JSON и REST API
- **Темы:** Стандартный пакет `net/http`: HTTP-клиент, HTTP-сервер; обработчики `http.Handler` и `http.HandlerFunc`; парсинг и сериализация JSON через `encoding/json` (структурные теги `json:"name,omitempty"`, десериализация потока `json.NewDecoder`); построение RESTful маршрутов (CRUD); написание собственного Middleware (логирование, аутентификация, recover); современные роутеры (встроенный в Go 1.22+ mux или `chi`).
- **Что должен уметь:** Создавать полноценные REST API сервисы с правильными HTTP-статусами, заголовками и безопасной валидацией входных данных.
- **Практические задания:** Разработка REST API для управления задачами (Todo API) или каталога товаров с CRUD-операциями и middleware логирования времени запроса.
- **Критерий усвоения:** Грамотная архитектура обработчиков, разделение слоев (handler -> service), безопасная обработка некорректного JSON без падений сервера.

### Этап 11. PostgreSQL, SQL и транзакции
- **Темы:** Реляционные базы данных; подключение через `database/sql` и драйвер `pgx`; пул соединений и его настройка (`SetMaxOpenConns`, `SetMaxIdleConns`); выполнение запросов `Query`, `QueryRow`, `Exec`; защита от SQL-инъекций через плейсхолдеры (`$1, $2`); работа с транзакциями `BeginTx`, `Commit`, `Rollback`; миграции схемы БД (инструмент `go-migrate`).
- **Что должен уметь:** Проектировать схемы таблиц, писать надежный слой доступа к данным (*Repository pattern*), безопасно проводить атомарные финансовые/бизнес-операции.
- **Практические задания:** Интеграция PostgreSQL в проект Todo API: сохранение, обновление статусов, фильтрация по датам, транзакционное удаление пользователя со всеми его задачами.
- **Критерий усвоения:** Использование пула соединений, правильное закрытие `rows.Close()`, исключение SQL-инъекций и корректный откат транзакций при ошибке.

### Этап 12. Тестирование и отладка
- **Темы:** Пакет `testing`; запуск `go test`; соглашения именования файлов `*_test.go`; модульные тесты (*Unit tests*); табличные тесты (*Table-driven tests*); вспомогательные методы `t.Helper()`, `t.Run()`; тестовые дублеры и моки интерфейсов; профилирование бенчмарков `testing.B`; запуск и анализ покрытия кода тестами `go test -cover`; отладка через дебаггер Delve (`dlv`).
- **Что должен уметь:** Покрывать код надежными табличными тестами, измерять производительность узких мест, находить баги с помощью отладчика.
- **Практические задания:** Полное тестовое покрытие слоя бизнес-логики ранее созданного REST API с мокированием базы данных.
- **Критерий усвоения:** Написание читаемых table-driven тестов, понимание разницы между `t.Errorf` и `t.Fatalf`, умение ставить брейкпоинты в VS Code/Delve.

### Этап 13. Docker, Git, CI/CD
- **Темы:** Контейнеризация Go-приложений: написание многоэтапного `Dockerfile` (*multi-stage build*) на базе `scratch` или `alpine` для получения минимального образа (<20 МБ); управление конфигурацией через переменные окружения (*12-Factor App*); `docker-compose` для одновременного запуска Go-приложения и PostgreSQL; настройка базового пайплайна GitHub Actions для автоматического запуска линтера (`golangci-lint`) и тестов при пуше.
- **Что должен уметь:** Упаковывать Go-сервис в легковесный защищенный контейнер, настраивать локальное окружение одной командой `docker compose up`, автоматизировать проверки через CI.
- **Практические задания:** Создание `Dockerfile` и `docker-compose.yml` для сервиса с БД, настройка GitHub Actions в репозитории `learning-go`.
- **Критерий усвоения:** Приложение успешно собирается в образ весом до 25 МБ, стартует в контейнере и связывается с PostgreSQL в отдельном контейнере.

### Этап 14. Алгоритмы и структуры данных
- **Темы:** Оценка сложности алгоритмов (Big O: временная и пространственная); алгоритмы поиска (линейный, бинарный); базовые сортировки и `sort.Slice`; связные списки, стек, очередь; хэш-таблицы под капотом; рекурсия; базовые деревья поиска; решение типовых алгоритмических задач уровня Easy/Medium.
- **Что должен уметь:** Оценивать асимптотическую сложность своего кода, выбирать оптимальные структуры данных под задачу, уверенно проходить алгоритмические секции собеседований.
- **Практические задания:** Реализация двусвязного списка, решение 15–20 задач на LeetCode на темы массивов, строк, указателей и хеш-таблиц.
- **Критерий усвоения:** Способность объяснить сложность по времени и памяти для любого написанного алгоритма.

### Этап 15. Практические проекты для портфолио
- **Темы:** Разработка двух законченных production-ready проектов с чистой архитектурой (*Clean Architecture / Hexagonal*):
  1. **REST API сервис сокращения ссылок (URL Shortener)** или **Трекер личных финансов/расходов** с аутентификацией (JWT/paseto), PostgreSQL, миграциями, кэшированием (Redis/in-memory), Docker и тестами.
  2. **Многопоточный сервис агрегации данных / парсер** с воркер-пулом, graceful shutdown, контекстами и метриками.
- **Что должен уметь:** Самостоятельно с нуля спроектировать архитектуру приложения, написать код, покрыть тестами, задокументировать (Swagger/OpenAPI) и развернуть сервис.
- **Практические задания:** Разработка, рефакторинг, проведение финального Code Review и оформление презентабельного README для портфолио.
- **Критерий усвоения:** Проект готов к показу на техническом собеседовании на позицию Junior Go Developer.
